## Outcome

Built the monthly compaction pipeline (#23): raw overlapping snapshots (63.7% duplicate rows, growing linearly) now merge into a deduplicated, `Parameter=<int>` hive-partitioned canonical store at `s3://water-temp-bc/data/canonical/` (98,726,492 rows / 0.37 GB vs 1.92 GB raw), with `data/canonical_meta.json` as both watermark and commit marker so failed months self-heal on the next run. `scripts/compact-functions.R` is the fixture-tested core (31 assertions in `scripts/compact-test.R`, written first, red-by-design); `scripts/compact.R` orchestrates S3 one partition per pass to bound runner disk forever; `snapshot.yml` gained the compact step plus a `compact_only` dispatch input for repair/bootstrap. Readers got the payoff live: latest-per-station across all BC stations collects in 1.3 s over the network (previously minutes), and `query_canonical()` lost its read-time dedup while keeping the `to_duckdb()` lazy contract. README rewritten quick-start-first with `source()`-from-raw-URL so users never clone.

The hard-won learnings (details in findings.md): duckdb's window operator OOMs unspillably at real volume (~124M-row partition, 8 GB limit); the arg_max hash-aggregate rewrite ALSO can't spill struct-payload state (and in-memory duckdb connections never offload — file-backed is required for any spill at all); the fix that works is hash-sharding each partition by STATION_NUMBER into `ceiling(rows/10e6)` sub-passes (159 s at the exact 4 GB/2-thread GHA profile). Production `Grade` is a double — a string coalesce sentinel in the dedup tiebreaker broke only on real data, so fixtures now mirror real column types. Two bucket-level items were redirected to rtj because `modules/s3` owns them (a CLI change would be reverted by the next tofu apply): the `NoncurrentVersionExpiration` lifecycle rule for canonical rewrites, and adding `s3:ListBucket` to the public policy — without which anonymous `arrow::open_dataset()` has never actually worked on this bucket (only direct-file GETs are credential-less today).
